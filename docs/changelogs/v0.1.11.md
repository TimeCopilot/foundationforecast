### Features

* **Known-future exogenous variables (`X_df`, `futr_exog_list`)**: Pass covariates for the forecast horizon via `FoundationForecast.forecast(..., X_df=..., futr_exog_list=...)`. Native model paths are used when supported; otherwise a linear **XReg** adjustment is fit on historical `(y, exog)` and applied at forecast time. Set `exog_strategy=False` on a forecaster to ignore exog inputs.

    ```python
    import pandas as pd
    from foundationforecast.models import Chronos

    df = pd.read_parquet(
        "https://timecopilot.s3.amazonaws.com/public/data/electricity_price/train.parquet"
    )
    X_df = pd.read_parquet(
        "https://timecopilot.s3.amazonaws.com/public/data/electricity_price/futr_exog.parquet"
    )

    model = Chronos(repo_id="amazon/chronos-2", alias="Chronos-2")
    fcst = model.forecast(df=df, h=24, X_df=X_df)
    assert "Chronos-2" in fcst.columns
    ```
* **Native futr exog** on Chronos-2, TimesFM-3, TimeGPT, T0 (beta), and TiRex-2, with validation that horizon exog covers every series and matches `futr_exog_list` before multi-model dispatch.
* **`experiments/fev-bench`**: Known-dynamic-only fev-bench grid (13 tasks), Modal CI replication for Chronos-2, TimesFM-3, T0-beta, and TiRex-2 on `epf_pjm` and `entsoe_1H`, mirroring the gift-eval experiment layout.

### Fixes

* **TimesFM-3 fev-bench replication**: Align `context_length` and model kwargs with the official fev submission (`max_context_length=15360`, `use_variate_attention`).
* **Chronos native exog**: Always request median quantile for point forecasts when using covariates.
* **Multi-model exog**: Validate exog support up front; omit exog kwargs when horizon data is missing.
* **XReg / validation**: Reject duplicate horizon keys, missing series in `X_df`, invalid `exog_strategy`, and `level`/`quantiles` combinations incompatible with the linear fallback.
