### Features

* **Prophet adapter**: New [`FoundationProphet`](https://docs.timecopilot.dev/foundationforecast/api/prophet/#foundationforecast.prophet.FoundationProphet), a `prophet.Prophet` subclass that runs any foundation model instead of the Stan model. Swap it into an existing Prophet pipeline in one line: `fit`, `make_future_dataframe`, `predict` (`ds`, `yhat`, `yhat_lower`, `yhat_upper`), `plot` and Prophet's `diagnostics.cross_validation` / `performance_metrics` keep working. See [#87](https://github.com/TimeCopilot/foundationforecast/pull/87).

    ```python
    from foundationforecast.models import Chronos
    from foundationforecast.prophet import FoundationProphet

    m = FoundationProphet(model=Chronos())  # instead of Prophet()
    m.fit(df)  # ds, y (+ regressors)
    future = m.make_future_dataframe(periods=30)
    forecast = m.predict(future)
    ```

* **Historical rows**: `make_future_dataframe(include_history=True)` is filled with rolling-origin backtest forecasts from `model.cross_validation` (`insample="cv"`, default), with a log message about the cost. `insample="none"` leaves them `NaN`; `insample_h` and `insample_n_windows` tune the windows.
* **Known-future regressors**: Columns registered with `add_regressor` are passed to the model as `X_df`, so they work with models that support native exogenous variables (e.g. Chronos-2).
* **Ignored Prophet arguments warn**: `holidays`, `growth`, seasonalities, changepoints, `add_seasonality` and `add_country_holidays` are accepted for compatibility but do not affect a foundation model, and a `UserWarning` now says so. Passing them as known-future exogenous variables is tracked in [#91](https://github.com/TimeCopilot/foundationforecast/issues/91).
* **Optional extra**: `prophet` is installed with `foundationforecast[prophet]`; `foundationforecast.prophet` is not imported by the package root.
